# Estimated Person Hours
The team estimated person-hours by breaking the Minesweeper system into major development tasks.
Each task was evaluated based on expected complexity, required implementation, testing effort, and documentation.

|            Task              | Estimated Hours |  Assigned Member(s)  |                                                                 Estimation Reasoning                                                                 |
|:----------------------------:|:---------------:|:--------------------:|:-----------------------------------------------------------------------------------------------------------------------------------------------------|
| MVP / Initial Implementation |        5        | Pruthviraj Sadhankar | Estimated at 5 hours due to the initial setup required to create a functional prototype containing the core board, gameplay, and interface features. |
|          Game Setup          |        5        | Gael Salazar-Morales | Estimated at 5 hours because this section contains several setup requirements, including board configuration, mine generation, user-selected mine counts, and first-click safety. |
|           Gameplay           |        5        |      Carter Ruff     | Estimated at 5 hours due to the number of gameplay features and the additional complexity of adjacent-mine calculations and recursive cell uncovering. |
|        Mine Flagging         |        3        |    Liam Kinghouser   | Estimated at 3 hours because the flagging requirements involve a smaller set of related features, including flag toggling, uncover restrictions, and remaining flag count calculations. |
|       Player Interface       |        4        |  Gabriel Haro-Villa  | Estimated at 4 hours due to the work required to display and update the board, cell states, mine count, and game status through the graphical interface. |
|       Game Conclusion        |        3        |   Joshua Fakunmoju   | Estimated at 3 hours because this section focuses on a limited set of related conditions for detecting wins and losses and updating the game accordingly. |
|        Documentation         |        5        |     Ivan Kullaya     | Estimated at 5 hours due to the amount of required documentation, including system architecture, diagrams, person-hour records, README maintenance, and final documentation review. |
|    Testing & Integration     |        6        |     All Members      | Estimated at 6 hours to allow time for integrating team contributions, testing requirements, identifying defects, and verifying the completed system. |
|  Meetings & Project Planning |        14       |     All Members      | Estimated at 14 person-hours to account for an approximately one-hour team meeting and one-hour GTA meeting involving all seven members for project planning, requirement review, task assignments, development coordination, and project evaluation. |
